# 依存技術の削除時の整合性チェック

## 目的

依存ツール、skill、旧配布方式を削除するとき、コード・ドキュメント・設定ファイルの全体で整合性を保ち、削除対象の痕跡を残さない。

## 背景

技術スタックや配布方式から特定の要素を削除した際、以下のような問題が起きやすい：

- コメントに古いツール名や旧パスが残る
- `mise.toml` や `apm.yml` に削除済みツールの定義が残る
- README.md、rules、specs に古い手順が残る
- APM 展開物や旧同期 symlink が正本のように残る

これらは読む人を混乱させ、実際には使わないツールのセットアップを試みるなどの無駄な作業を誘発する。

## チェックリスト

削除対象の名前・パス: `{name}`

### 1. コード内の参照

- [ ] **docstring/コメント内の言及**
  ```bash
  rg "{name}"
  ```
- [ ] **mise.toml**
  - 依存定義
  - コメント（使用目的の説明など）
- [ ] **apm.yml / apm.lock.yaml**
  - skill の依存定義
  - lockfile に残る不要な package
- [ ] **scripts/**
  - 実行スクリプト内の呼び出し

### 2. ドキュメント内の参照

- [ ] **README.md**
  - セットアップ手順
  - コマンド例
  - 前提条件
- [ ] **rules/**
  - 横断方針やチェックリスト
- [ ] **specs/**
  - 現在仕様
- [ ] **skills/**
  - SKILL.md、references、assets 内の説明
- [ ] **decisions/**
  - Decision Record内の言及（履歴として残すべきかを判断）
  - 削除理由を新しいDRに記録することも検討

### 3. 設定ファイル

- [ ] **.gitignore**
  - 削除ツール固有のパターン
- [ ] **CI/CD設定**
  - GitHub Actions / CircleCI / その他
  - ワークフロー定義
  - タスク定義
- [ ] **環境変数**
  - `.env.example`
  - ドキュメント内の環境変数説明
  - API キー関連の記述

### 4. スクリプト・タスク定義

- [ ] **mise.toml**
  - タスク定義
  - タスクの説明コメント

## 検索コマンド例

```bash
# decisions/を除外して全検索
rg "{name}" --glob '!decisions/**'

# 特定ディレクトリのみを対象に検索
rg "{name}" README.md AGENTS.md rules specs skills mise.toml apm.yml
```

## 原則

- **コードを変えたら、ドキュメントも同じPRで更新する**
- **decisions/は履歴として残す**（過去の判断を消さない）
- **痕跡がある場合は意図的か確認**（コメントアウト等で一時的に残している可能性）
- **APM 展開物や旧同期出力は正本にしない**（必要なら `.gitignore` に戻り防止を書く）
