# skill を変える前に問題の再現を確かめる

## 目的

効果を確かめていない変更を skill に入れない。

## 背景

- レビューや監査で見つかる skill の問題は、ファイルを読んだうえでの推測であることが多い
- 推測だけで直すと、起動する skill が変わらなかったり、足した一文で出力が悪くなったりする

## ルール

- skill（`skills/<skill-name>/` 配下）を変える前に、今の main の skill で、その問題が実際に起きることを確かめる
- 起きなかった問題は直さない
- 直したら、同じ依頼で変更前と変更後を比べ、想定どおりに動くことを確かめてから PR にする
- 誤字、リンク切れ、存在しないパスのように、ファイルを読めば問題が確定するものは、再現を確かめなくてよい

## 確かめ方

- 使い捨てのリポジトリを作り、main の `skills/` を `.claude/skills/` にコピーする
- 問題が起きるはずの依頼文を `claude -p --output-format stream-json --verbose` に渡し、呼ばれた skill、読んだファイル、最終回答を見る
- 1 つの依頼文につき、モデルを変えて複数回走らせる。1 回の結果では判断しない
- 利用先の環境に組み込みの skill があるときは、それも起動候補に入った状態で試す

## 注意

- 実験中に、ほかの skill が実際に script を走らせることがある。終わったら `~/.claude/` や `/tmp` に一時ファイルが残っていないかを確かめ、残っていれば消す
- Cursor など、Claude Code 以外の環境で試していないときは、報告で「未確認」と書く
