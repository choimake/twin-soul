# スコープが明確か

## ねらい

スコープが曖昧だと、「何を作るのか」「何を作らないのか」が不明確になり、実装範囲が膨らむ。
明確なスコープ定義で、実装者が迷わず進められるようにする。

## チェック観点

- 目的セクションに「達成したいこと」が明確に書かれているか
- 実装方針に「やること」と「やらないこと」の境界が見えるか
- 変更対象ファイルセクションでファイルが特定されているか
- スコープ外の作業が明示されているか（必要に応じて）

## 指摘する基準

- 目的セクションが無い、または「良い感じにする」のような曖昧な表現の場合は **重大** として指摘する
- 実装方針から、何をどの順で変えるかが読み取れない場合は **提案** として指摘する
- スコープ外の作業が曖昧な場合は **提案** として指摘する

## 例

### 悪い例（曖昧すぎる）

```markdown
## 目的

パスワードリセットを作る

## 実装方針

1. ファイルを作る
2. テストする
```

### 良い例（スコープが明確）

```markdown
## 目的

ログインできなくなったユーザーが、登録メール宛のリンクから自分でパスワードを再設定できるようにする。

## 実装方針

### Phase 1: トークンの発行と検証

1. `src/auth/password_reset.ts` にトークンの発行と検証を実装する
2. `src/routes/auth.ts` に `/password-reset` ルートを追加する

## スコープ外

- メール送信の仕組みの変更
- メール以外（SMS など）での本人確認
```

## 補足

- スコープは「達成したいこと」と「達成しないこと」の両方を明確にする
- 変更対象ファイルセクションでファイルを列挙することで、スコープが具体化される
