# 検証手順が具体的か

## ねらい

検証手順が無いと、「実装が完了したかどうか」を確認できない。
コマンド例と期待結果を明示することで、実装者とレビュアーが同じ基準で検証できる。

## チェック観点

- 検証セクションが存在するか
- 各検証項目に **コマンド例** が含まれているか
- 各検証項目に **期待結果** が含まれているか
- 各検証項目に、**実行したときに不合格だと分かる観測**（終了コード、欠落、不一致）があるか
- 前後比較（減った・短くなった）を書く場合、比較前の実測を `critical-assumptions-resolved.md` の Phase 0 に置いているか。絶対閾値は対象外
- 「確認する」だけの曖昧な表現になっていないか
- 検証が lint・CI・テストの緑だけで終わっていないか。成果物（変更した本文・画面・実ファイル）を見る項目があるか

## 指摘する基準

- 検証セクションが無い、または空の場合は **重大** として指摘する
- コマンド例が無い、または「確認する」だけの曖昧な表現の場合は **重大** として指摘する
- 期待結果に、実行時の不合格観測が無い場合は **重大** として指摘する
- 前後比較を書いたのに比較前の実測が Phase 0 に無い場合は **重大** として指摘する
- 検証が lint やテスト緑だけで、成果物を見ていない場合は **重大** として指摘する
- 期待結果が不明確な場合は **提案** として指摘する

## 例

### 悪い例（lint 緑だけで完了）

````markdown
## 検証

```bash
npm run lint
```

期待結果: 終了コード 0
````

lint が緑でも、未登録メールに 202 を返すかどうかは観測できない。

### 悪い例（曖昧すぎる）

```markdown
## 検証

- ファイルが作成されたことを確認する
- テストが通ることを確認する
```

### 良い例（コマンド例と期待結果が明確）

````markdown
## 検証

### テスト

```bash
npm test -- tests/auth/password_reset.test.ts
```

期待結果: 終了コード 0 で、失効と未登録メールのケースが実行件数に含まれる
不合格の観測: 非ゼロで終わる、または該当ケースが実行件数に無い

### 未登録メールへの応答

```bash
curl -s -o /dev/null -w '%{http_code}' -X POST http://localhost:3000/password-reset -d 'email=unknown@example.com'
```

期待結果: `202` が出力される
不合格の観測: `404` など `202` 以外が出力される
````

## 補足

- 検証手順は「実装者が自己チェックできる」レベルの具体性を持つ
- コマンド例はコピペで実行できる形式が望ましい
- 期待結果は「何が確認できれば OK か」と「何が見えたら不合格か」を明示する
- lint やテストが緑でも、成果物を見ていない検証は完了にしない
