# 検証手順が具体的か

## ねらい

検証手順が無いと、「実装が完了したかどうか」を確認できない。
コマンド例と期待結果を明示することで、実装者とレビュアーが同じ基準で検証できる。

## チェック観点

- 検証セクションが存在するか
- 各検証項目に **コマンド例** が含まれているか
- 各検証項目に **期待結果** が含まれているか
- 各検証項目に、**実行したときに不合格だと分かる観測**（終了コード、欠落、不一致）があるか
- 前後比較（減った・短くなった）を書く場合、比較前の実測を `critical-assumptions-resolved.md` の Phase 0 に置いているか。絶対閾値は対象外
- 「確認する」だけの曖昧な表現になっていないか
- 検証が `mise run ci:lint` やテスト緑だけで終わっていないか。成果物（変更した本文・画面・実ファイル）を見る項目があるか

## 指摘する基準

- 検証セクションが無い、または空の場合は **重大** として指摘する
- コマンド例が無い、または「確認する」だけの曖昧な表現の場合は **重大** として指摘する
- 期待結果に、実行時の不合格観測が無い場合は **重大** として指摘する
- 前後比較を書いたのに比較前の実測が Phase 0 に無い場合は **重大** として指摘する
- 検証が lint やテスト緑だけで、成果物を見ていない場合は **重大** として指摘する
- 期待結果が不明確な場合は **提案** として指摘する

## 例

### 悪い例（lint 緑だけで完了）

````markdown
## 検証

```bash
mise run ci:lint
```

期待結果: 終了コード 0
````

`ci:lint` が緑でも、足した禁止が本文に無い不合格を観測できない。

### 悪い例（曖昧すぎる）

```markdown
## 検証

- ファイルが作成されたことを確認する
- テストが通ることを確認する
```

### 良い例（コマンド例と期待結果が明確）

````markdown
## 検証

### lint

```bash
mise run ci:lint
```

期待結果: 終了コード 0
不合格の観測: 非ゼロ

### 禁止が本文にあるか

変更した `SKILL.md` または knowledge を読み、足した禁止があることを確認する。

期待結果: 該当する禁止が本文にある
不合格の観測: lint は緑だが、該当禁止が無い

### 構造チェック

\```bash

# ディレクトリ構造が正しいことを確認

ls -la skills/planner/
ls -la skills/planner/assets/
ls -la skills/planner/references/
\```

期待結果: `SKILL.md`, `assets/`, `references/` が存在する
不合格の観測: いずれかが無い、または `ls` が非ゼロで終わる

### 動作テスト

\```bash

# Claude Codeで /planner コマンドを実行

/planner draft --task "新機能の追加"
\```

期待結果: plan file が生成され、必須セクション（背景, 目的, 受け入れ条件, ベストプラクティス, 検証）が含まれる
不合格の観測: 必須セクションが欠けた本文、またはコマンドが plan を出さない
````

## 補足

- 検証手順は「実装者が自己チェックできる」レベルの具体性を持つ
- コマンド例はコピペで実行できる形式が望ましい
- 期待結果は「何が確認できれば OK か」と「何が見えたら不合格か」を明示する
- lint やテストが緑でも、成果物を見ていない検証は完了にしない
