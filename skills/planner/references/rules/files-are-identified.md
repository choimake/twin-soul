# 変更対象ファイルが特定されているか

## ねらい

変更対象ファイルが特定されていないと、「どこを触ればよいか」が不明確になり、実装が迷走する。
変更対象ファイルセクションで明示することで、実装範囲を具体化する。

## チェック観点

- 変更対象ファイルセクションが存在するか
- 新規作成ファイルと既存ファイル更新が分けて列挙されているか
- 各ファイルに簡潔な説明が付いているか
- ファイルパスが具体的か（`path/to/file` のような形式）

## 指摘する基準

- 変更対象ファイルセクションが無い、または空の場合は **重大** として指摘する
- ファイルパスが曖昧（例: "適当なファイル"、"必要なファイル"）な場合は **提案** として指摘する
- 新規作成と既存更新が混在している場合は **提案** として指摘する

## 例

### 悪い例（曖昧すぎる）

```markdown
## 変更対象ファイル

- 適当なファイル
- 必要なファイル
```

### 良い例（具体的）

```markdown
## 変更対象ファイル

### 新規作成ファイル

- `skills/planner/SKILL.md` - メイン定義（500行未満）
- `skills/planner/assets/plan-template.md` - plan fileテンプレート
- `skills/planner/references/planner-knowledge.md` - 判断基準と詳細ロジック

### 既存ファイル更新

- `README.md` - skillsリストに `planner` を追加
- `apm.yml` - package metadata や target を必要に応じて更新
```

## 補足

- 変更対象ファイルは「実装者が何を触ればよいか」を明確にする
- 新規作成と既存更新を分けることで、既存コードへの影響範囲が見える
- 各ファイルに簡潔な説明を付けることで、役割が分かりやすくなる
