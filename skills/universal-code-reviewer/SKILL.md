# Universal Code Reviewer

## 目的

スコープ外は見ない。`@path` 未指定なら確認を求める。コンテキスト爆発より的確な絞り込みを優先する。

## 使う場面

- 「レビューして」「見て」「チェックして」「改善点ある？」などコードレビュー依頼時
- `@path` 付きでファイル・フォルダを指定してレビューを求めたとき
- デッドコード・コメント整合・意図コメント・TODO 運用・命名整合をまとめて確認したいとき

## 手順

1. レビュー対象のスコープを特定。`@path` があればその範囲を優先、なければ `@path` 指定を依頼。
2. 「差分だけ」と明示された場合のみ変更差分を対象にする。明示なしで diff review へ寄せない。
3. スコープ内のファイルに対して `references/rules/` 配下のルール文書をファイル名順で適用。
4. スコープだけでは判断できない場合のみ、必要最小限で追加確認・スコープ拡張を提案。
5. 指摘はルール名と優先度が分かる形で重要度の高い順に返す。必要なら最小限の修正案を添える。
6. 指摘なしの場合もその旨を明示し、残る不確実性や未確認範囲があれば短く添える。

詳細判断と出力ルールは [references/universal-code-reviewer-knowledge.md](references/universal-code-reviewer-knowledge.md) を参照。出力の骨格は [assets/review-output-template.md](assets/review-output-template.md) を使用。

## 期待する出力

- スコープを限定したレビュー方針
- `references/rules/` の観点に対応づいた指摘一覧、または指摘なしの明示
- 必要最小限の追加確認事項・小さな修正案・または残る不確実性
