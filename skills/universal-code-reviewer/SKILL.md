# Universal Code Reviewer

## 目的

コードレビューの汎用チェック観点をそろえ、スコープを絞ったまま一貫した指摘を返す。他所が壊れうる変更では、安全だと言える1事実を実行で示す。

## 使う場面

- コードや PR の変更のレビュー・改善点の確認を求められたとき
- `@path` でファイル・フォルダを指定してレビューを求められたとき
- デッドコード・コメント整合・コメントの Why not・コミットメッセージの Why・TODO 運用・命名整合を、まとめて、またはどれかに絞って確認したいとき
- 変更が他所を壊さないかを確かめたいとき

## 手順

1. レビュー対象のスコープを特定。`@path`、または「差分だけ」「PR の変更だけ」のようなスコープ指示があればその範囲を対象にし、どちらも無ければ `@path` 指定を依頼。
2. 「差分だけ」「PR の変更だけ」のように変更差分に絞る指示がある場合のみ、変更差分を対象にする。指示が無ければ diff review へ寄せない。
3. スコープ内のファイルへ `references/rules/` 配下のルールドキュメントをファイル名順で適用する。観点やルール名に絞る指示があれば、そのルールだけを適用する。
4. 他所が壊れうる変更なら、安全だと言える1事実を実行で示す。呼び出しの列挙や説明だけでは足りない。示せないなら未証明と書く。適用の判断は knowledge を参照。
5. スコープだけでは判断できない場合のみ、必要最小限で追加確認・スコープ拡張を提案。
6. 指摘はルール名と優先度が分かる形で重要度の高い順に返す。必要なら最小限の修正案を添える。
7. 指摘なしの場合もその旨を明示し、残る不確実性や未確認範囲があれば短く添える。

詳細判断と出力ルールは [references/universal-code-reviewer-knowledge.md](references/universal-code-reviewer-knowledge.md) を参照。出力の骨格は [assets/review-output-template.md](assets/review-output-template.md) を使用。

## 期待する出力

- スコープを限定したレビュー方針
- `references/rules/` の観点に対応づいた指摘一覧、または指摘なしの明示
- 他所が壊れうる変更では、安全だと言える1事実の証明、または未証明
- 必要最小限の追加確認事項・小さな修正案・または残る不確実性
