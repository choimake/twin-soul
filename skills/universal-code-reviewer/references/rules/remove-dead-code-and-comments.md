# 不要なコード/コメントは削除する

## ねらい

不要なコードやコメントは可読性を下げ、保守コストを増やす。
特に **デッドコード/デッドコメント** は、後から読む人に「今も有効なのか？」という不要な判断コストを強いる。

## チェック観点

- **使われていないコード**（呼ばれない関数、未参照の変数、到達しない分岐）が残っていないか
- **役に立たないコメント**（コードをそのまま言い換えただけ、古い仕様の名残）が残っていないか
- 一時的な回避策や実験コードが残っていないか（残すなら TODO/Issue 化して期限/背景を明記）

## 指摘する基準（境界）

- 「削除」を指摘するのは、**現スコープ内で未参照/未到達と判断できる** 場合を基本とする（外部参照が疑われるならスコープ拡張候補として提示する）
- コメントは、**情報が増えていない単なる言い換え**（What の重複）なら削除候補とする
- 「一時的」なコードを残す場合は、**追跡先（Issue/PR/DR）** または **期限** のどちらかが最低限必要

## 例

### 悪い例（使われないコードが残っている）

```java
public void processOrder(Order order) {
    // オーダーを処理する
    if (order != null) {
        // order.process(); <-- このコードはもう使用されていないので削除する

        // 新しい処理
        processOrderNew(order);
    }
}
```

### 良い例（不要部分を削除して意図を残す）

```java
public void processOrder(Order order) {
    if (order == null) {
        return;
    }
    processOrderNew(order);
}
```

## 補足（残すべき情報がある場合）

- 「なぜ削除したのか」「置き換え先は何か」といった意図は、コメントよりも **PR 本文 / DR / Issue** に残すほうが整合性を保ちやすい
- コード内に残す必要があるなら、**意図（Why）** と **期限/追跡先**（Issue 番号等）をセットで書く
