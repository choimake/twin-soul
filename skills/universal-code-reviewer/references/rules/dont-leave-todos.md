# TODOコメントを放置しない

## ねらい

TODO/FIXME を放置すると、いつまでも着手されず「負債の見える化」ではなく「負債の放置」になる。
残すなら、**いつ/誰が/何を** するのかを追跡可能にする。

## チェック観点

- TODO/FIXME が **放置** されていないか（追跡先も期限も無い）
- 残す必要があるなら、Issue 化などで **追跡可能** になっているか
- TODO が「仕様の穴」や「設計判断の未完」を示す場合、DR/ドキュメントで補うべきではないか

## 指摘する基準（境界）

- 追跡先（Issue/PR/DR）も期限も無い TODO/FIXME は「放置」とみなし、原則指摘する
- TODO が「後で直す」以上の意味（仕様未決・設計の保留）を含む場合は、**ドキュメント化（DR）** も提案する

## 例

### 良い例（次アクションが追跡できる）

```java
public void calculateDiscount(Order order) {
    // TODO: 複雑なロジックの最適化が必要
    // - 次のスプリントで対応
    // - Issue #13 としてチケット化済
    if (order.isPremium()) {
        order.setDiscount(20);
    } else {
        order.setDiscount(10);
    }
}
```

## 補足（推奨運用）

- TODO を残すなら、最低限「追跡先（Issue/PR/DR）」か「いつ対処するか」のどちらかを付ける。理由だけの TODO は指摘する。理由も書けるなら添える
- TODO が増え続ける箇所は、スコープを切って「負債返済 PR」を作る判断もする
