# 手書きルールを保持しているか

## ねらい

既存 `.gitignore` の手書きルールや project 固有ルールを無断で削除すると、意図的な ignore 設定が失われ、機密ファイルや生成物が commit されるリスクがある。

## チェック観点

- 既存の手書きルールや project 固有ルールをむやみに消していないか
- `gitignore.io` の生成ブロックと手書きルールを区別して読んでいるか
- 何を追加し、何を維持し、何を削るかを分けて提案しているか
- 判別しにくい項目を理由なく削除していないか

## 指摘する基準

- 既存の手書きルールを無断で削除している場合は **重大** として指摘する
- 全面置換を提案している場合は **提案** として指摘する（差分更新を推奨）
- 判別しにくい項目を理由なく削除している場合は **提案** として指摘する

## 例

### 悪い例

```gitignore
# 既存 file を gitignore.io の出力で全面置換し、
# project 固有の /secrets/local/ ルールを削除
```

### 良い例

```markdown
## 維持
- /secrets/local/  （project 固有、手書き追加）

## 追加
- .terraform/
- *.tfstate
```

## 補足

- `# Created by https://www.toptal.com/developers/gitignore/api/...` の見出し以降にも手書きルールがあり得る
- 全面置換ではなく、差分ベースで扱う
