# 用語集とストーリー対応が整備されているか（ユースケース記述）

## ねらい

用語の揺れは仕様の揺れとして実装に伝播する。本文で使った用語を用語集で固定し、各ユースケースが元のストーリーへ紐づく状態を保つことで、下流（機能要求・受入基準）への展開と逆引きを可能にする。

## チェック観点

- 用語集があり、本文で使った主要な用語（ドメイン語・システム側の処理名）を定義しているか
- 本文の語と用語集の語が一致しているか（同じ概念に別の語を使っていないか）
- 定義が曖昧語（「適切に」「うまく」等）で終わっていないか
- 各ユースケースに対応ストーリー（ID または参照）が明記されているか

## 指摘する基準

- 用語集が無い、または本文の主要用語と食い違う場合は **提案**
- 対応ストーリーへの紐づけが無い場合は **提案**
- 用語集はあるが英語表記や参照（前提 A 番号等）が欠けている場合は **任意**

## 例

### 悪い例

```markdown
1. 訪問者が URL へアクセスすると、システムはページを配信する。
```

（「URL」「ページ」が本文の他の箇所では「入稿 URL」「LP」と呼ばれており、用語集にも無い）

### 良い例

```markdown
## 用語集

| 用語 | 英語 | 定義 |
| --- | --- | --- |
| 入稿URL | Destination URL | 広告媒体等へ遷移先として入稿される URL（A2） |
| 配信 | Delivery | 入稿URLへのアクセスに対し、システムが LP コンテンツをレスポンスとして返すこと |
```

## 補足

- 用語集は代替・例外フローの分類（一時的／恒久的な障害等）も定義しておくと、例外フロー間の整合が取りやすい
