# README 判断知識

この資料は `readme` skill の判断知識をまとめたものである。`SKILL.md` は使い方に留め、新規作成や全面改稿はテンプレートを起点にする。

テンプレート:

- [../assets/readme-template.md](../assets/readme-template.md)

## README の役割

README はスタート地点であり、詳細資料の置き場ではない。

初見の人が次の 4 点を短時間で理解できる状態を目指す。

- 概要: 何をするプロジェクトか
- なぜ必要か: なぜ有用か
- はじめ方: どう始めるか
- サポート: 困ったときにどこを見るか

## README に残すもの

- 何をするプロジェクトか
- なぜ使う価値があるか
- 最短の開始手順
- 代表的な次の行動
- サポート先、メンテナ、関連文書への案内

## README から出すもの

- 長い解説、詳細仕様、完全な手順書: `docs/` や Wiki
- 貢献ルール: `CONTRIBUTING.md`
- 行動規範: `CODE_OF_CONDUCT.md`
- API リファレンス、運用手順、設計史、比較検討の全文

README は案内板に徹し、詳細は相対リンクで別文書へ逃がす。

章立てはテンプレートを基本にする。必要なら短い補助セクションを足してよいが、入口文書としての短さを崩さない。

## レビュー時の判定

既存 README が与えられていて依頼が曖昧なら、まずレビューとして扱う。

レビューでは次を優先して確認する。

- README 冒頭だけで概要と価値が分かるか
- 初回の行動がすぐ見つかるか
- 困ったときの参照先やサポート先があるか
- 詳細情報を README に抱え込みすぎていないか
- 何を README に残し、何を別文書へ逃がすかを明示できているか
- 章立てがテンプレートの骨格から大きく逸れていないか

## 迷ったときの判定

次の質問のどれかに `No` が付くなら、README を短くする方向を優先する。

1. これは初見の人が最初の一歩を踏み出すために必要か
2. これは数段落以内で伝えられるか
3. 詳細は別文書に逃がしても困らないか
4. README には導線だけを残せば十分か
