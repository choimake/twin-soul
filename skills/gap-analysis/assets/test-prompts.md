# gap-analysis 向けテストプロンプト

手動またはエージェント試行時に使う。成功基準は各ブロック下に記載。

## 1. 典型

**依頼例**: 「添付の PRD 抜粋と、昨日のスパイクメモから Gap 分析表を Markdown で出して。環境は dev クラスタ、検証日は 2026-04-18。」

**確認**: 表紙メタ・判定凡例・各要件の 6 行表・サマリが揃う。判定が凡例と整合する。

## 2. 境界（証拠不足）

**依頼例**: 「この PRD のネットワーク要件だけ Gap 分析して。ログはまだ取れていない。」

**確認**: 「未検証」または「要追加検証」が使われ、推測と事実が分離されている。

## 3. 要件 ID が無い入力

**依頼例**: 「PRD には章番号しかない。連番は付けず、見出しは短い日本語ラベルだけで Gap 表を作って。」

**確認**: 新規に T-01 などを付与していない。見出しとサマリ列がラベルで一貫している。

## 4. 近接タスク（対象外の境界）

**依頼例**: 「来スプリントの PBI を 3 件起票して。受入基準も書いて。」

**確認**: 本 skill の主成果物（PRD と証拠の突合表）ではないため、依頼のまま進まず、Gap 分析が必要なら別依頼として切り出す説明ができる（または対象外を明示）。
