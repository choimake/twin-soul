# 複数モデルの議論で案を決める

## 目的

1つのモデルの癖で案の形が決まるのを避ける。異なるモデルに独立して案を出させ、互いの案を読ませて批評と改訂を回し、残った合意と対立を根拠つきでまとめる。オーケストレーター（この skill を実行しているエージェント）は進行と統合だけをし、議論中に自分の案を出さない。

## 使う場面

- 設計案・施策・運用方針など、正解が1つに決まらない議題で、複数の案を戦わせてから決めたいとき
- 1回の相談だと最初に出た案の形で固まりそうなとき

## 手順

1. **議題を固める**: 議題、背景、制約、議論役に読ませる材料（リポジトリ内のパス）、評価基準を 3〜6 個決める。評価基準は「この議題で何ができていれば良い案か」を、比べられる形で書く。議題か制約が会話から読み取れなければユーザーに聞く。議題に秘密情報を入れない。議題は複数の外部サービスへ送られる。
2. **席と上限を決める**: 「起動時の指定 → リポジトリのルートの `.multi-model-debate.yaml` → ユーザーに聞く」の順で、席（CLI とモデルの組）を 2〜3 個、上限回数、時間の上限を確定する。どこにも無ければ、上限回数は 2 回、時間の上限は全体 600 秒・出力が止まってから 120 秒にする。同じ組を2席に置かない。指定されたモデルが今の環境で呼べるかは、着手前に確かめる。`.multi-model-debate.yaml` が無ければ、[assets/multi-model-debate-config.yaml](assets/multi-model-debate-config.yaml) を `.multi-model-debate.yaml` としてルートに置き、ルートの `.gitignore` に `.multi-model-debate.yaml` を足してよいか聞く。了承されたらコピーして `.gitignore` に足す。中身は埋めず、今回の席はその場で聞いて進める。使えるツールとモデルは環境ごとに違うので、このファイルはコミットしない。
3. **着手前に提示する**: 議題、評価基準、各席の CLI とモデル、上限回数、時間の上限を箇条書きで見せてから始める。
4. **作業場所を作る**: 一時ディレクトリに `debate-<議題の短い名前>/` を作り、議題・背景・制約・材料のパス・評価基準を `agenda.md` に書く。各ラウンドの出力は `round-<n>/<席>.md` に置く。席の名前は A・B・C にし、議論役にはモデル名を見せない（どのモデルの案かで評価が偏るのを避ける）。
5. **ラウンド 1（独立案）**: [assets/debater-brief.md](assets/debater-brief.md) の「ラウンド 1」に `agenda.md` を埋めて、全席を並列に実行する。互いの案は渡さない。
6. **ラウンド 2 以降（批評と改訂）**: 同じ雛形の「ラウンド 2 以降」に、自分の直前の案と他の席の直前の案を全文埋めて、全席を並列に実行する。オーケストレーターの評価や要約は渡さない。
7. **打ち切る**: 全席の1行目が「変更なし」になるか、上限回数に達したら止める。
8. **まとめる**: 最後の案を評価基準ごとに比べ、推奨案1つと代替案を決める。席の数が多い案を自動で選ばない。基準ごとの比較で選び、理由を書く。議論に出ていない根拠を足すときは、オーケストレーターの判断だと明示する。最後まで割れた点は平均せずに割れたまま書く。どの席も議題の前提を疑っていたら、議題の立て方を見直すよう提案する。
9. **報告する**: [assets/report-template.md](assets/report-template.md) の形で返す。

## 議論役の呼び出し

呼び出し方（CLI の非対話モード、サブエージェントなど）は、実行する環境でオーケストレーターが決める。守るのは次のとおり。

- 席ごとに指定したモデルが実際に使われる経路で呼ぶ
- 読み取り専用で動かし、材料のあるリポジトリを読める場所で実行する
- 同じラウンドの席は並列に動かし、全席がそろってから次へ進む
- 各席は、この skill の [scripts/run-seat.py](scripts/run-seat.py) を通して呼ぶ。止める仕組みを自分で書かない。全体の上限を過ぎるか、出力が止まってから決めた秒数が過ぎると、プロセスグループごと TERM を送り、残っていれば KILL する
  - 例: `python3 <skill のディレクトリ>/scripts/run-seat.py --out round-1/A.md --stdin round-1/A.prompt --timeout 600 --idle 120 -- claude -p --model opus`
- 終了コードが 3（出力が止まったので止めた）か 124（全体の上限で止めた）のときは、指示した見出しが最後まで出ていれば回答として使い、出ていなければ失敗として扱う
- ほかの席には、議論役の最終回答だけを渡す。途中経過や内部のやりとりが出力に混ざっていたら取り除く
- 出力が空か失敗した席は1回だけやり直す。それでも失敗したら、その席を外して報告に書く。残りが2席を下回ったら止めて、ユーザーに聞く

## 制約

- 議論役にファイルを変えさせない。案の実装はこの skill の外でする
- オーケストレーターは議論中に案を出さず、どの席にも肩入れしない
- 議論役の出力は、根拠を確かめる前に事実として報告しない。コードや文書に関する主張は、まとめの段階で該当箇所を読んで確かめる。確かめていないものは「未確認」と書く

## 期待する出力

- 着手前: 議題・評価基準・席・上限回数の提示
- 終了後: 推奨案、代替案、評価基準ごとの比較、合意した点、残った対立（どの席が何を理由に）、採らなかった案と理由、ラウンドの経過、外れた席

## 検証

- 着手前に席と上限回数を見せている
- ラウンド 1 で互いの案を渡していない
- ラウンド 2 以降にオーケストレーターの評価を混ぜていない
- 推奨案の理由が評価基準に結びついていて、席の数だけで決めていない
- 割れた点と外れた席が報告に残っている
