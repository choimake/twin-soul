# 合議調査（N 体独立実行×確度付け）

## 目的

メインエージェントは割り振りと突合だけする。同一の調査を複数の調査サブエージェントへ独立に渡し、結果の突合・確度付け・統合報告に限る。指摘の出現数を確度に変換する（全員一致 = 高、過半 = 中、それ以外 = 低）。

## 使う場面

- 調査・レビュー結果の実行ごとのばらつきを抑え、指摘に確度を付けたいとき
- universal-code-reviewer などの調査系 skill の手順を、複数体で独立実行して確度付きに強化したいとき
- gap-analysis のような判定型の調査で、判定の割れを「要確認」として可視化したいとき

## 手順

調査対象とスコープは直前のユーザー指示から取る。

1. **適用判定**: 依頼が調査系タスク（成果物が指摘・判定・情報であり、対象を変更しない）であることを確認する。実装・修正・ドキュメント作成など変更を伴うタスクなら本 skill を適用せず、その旨と代替（実装×レビューのループなら verification-loop）を伝えて終了する。判定基準は [references/consensus-investigation-knowledge.md](references/consensus-investigation-knowledge.md) の「適用判定」を参照。
2. **モード分岐**: 何を測るかを決める。同一依頼の再現性なら合議として続ける。範囲を分けて並列に調べるなら合議ではない。出現数確度を付けず、通常の並列調査として扱う旨を伝えて終了する。複数案から最良を取るなら本 skill の対象外として終了する。担当分けもしない。判定例は knowledge の「モード分岐」を参照。
3. [config/defaults.yaml](config/defaults.yaml) を読む。
4. 調査対象・スコープ・併用する調査系 skill（あれば SKILL.md のパス）を確定する。対象 skill 側の手順にユーザー確認があるなら、渡す前にメインエージェントが解決する。
5. エージェント数とモデルを「呼び出し引数 → defaults.yaml → 未確定ならユーザー確認」の順で確定する。手順 4〜5 の詳細判断は knowledge を参照。
6. 確定した対象・対象 skill・エージェント数・モデルを箇条書きで提示してから着手する。
7. **並列に渡す**: 同一の依頼文で `agent_count` 体の調査サブエージェントを並列起動する。対象 skill があれば「その SKILL.md を読み手順に従う」指示を含める。互いの結果・メインエージェントの仮説は渡さない。指摘は構造化フォーマット（位置・分類・重要度・主旨・根拠）で全件返させる。含める項目は knowledge の「調査に渡す項目」を参照。
8. **突合**: 位置と分類でグルーピングし、主旨の意味的同一性をメインエージェントが判定して指摘ごとの出現数を数える。判定投票型（固定項目への判定）の集計は knowledge を参照。
9. **確度付け**: 出現数が N（全員一致）なら高、過半なら中、それ以外なら低とする。単独指摘も捨てずに低確度として残す。
10. **統合報告**: [assets/consensus-report-template.md](assets/consensus-report-template.md) で確度順に報告する。確度は再現性の指標であり正しさの保証ではない旨を必ず添える。

## 制約

- 調査サブエージェントに対象の変更をさせない。渡すのは読み取り専用の調査だけとする。調査の結果として修正が必要になっても、修正は本 skill の外でする
- メインエージェントは調査本体を自分でやらない。結果に不足があれば、新しい調査サブエージェントを追加で立てる
- 確度を理由にメインエージェントが指摘を除外しない。採否はユーザーが判断する
- 担当分け（セキュリティ担当・性能担当のような分担）はしない。分担すると出現数が確度として機能しなくなる。分担調査が目的なら本 skill を使わず通常の並列調査として扱う

## 期待する出力

- 確定した調査対象・対象 skill・エージェント数・モデルの提示（着手前）
- 確度順の統合レポート（指摘 / 出現数 / 確度 / 位置 / 根拠）
- 判定投票型では項目ごとの判定分布と、割れた項目の「要確認」明記
- 確度の意味（再現性であり正しさの保証ではない）の注意書き

## 検証

- 変更を伴うタスク（実装・修正・ドキュメント作成）に適用していない
- スライス並列と最良採用では合議手順を回していない
- メインエージェントは割り振りと突合に限り、調査本体を自分でやらない
- 調査サブエージェント間で結果・仮説を共有していない
- モデル識別子が skill 本文にハードコードされていない
- `config/defaults.yaml` と引数の解決順が手順に書かれている
- 単独指摘が低確度として報告に残っている
- 確度を「正しさの保証」として報告していない
