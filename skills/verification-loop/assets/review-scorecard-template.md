# レビュー スコアカード

レビュー結果は次の骨格を起点に組み立て、ラウンドディレクトリの `scorecard.md` に書く。基準は渡された合格基準を列挙し、それぞれ採点する。

```md
## スコアカード

### 基準ごとの採点

| 基準 | スコア (0.0–1.0) | 要旨 |
| ---- | ---------------- | ---- |
| [基準1] | 0.0 | [一行で] |
| [基準2] | 0.0 | [一行で] |

### 根拠

| 基準 | 場所 | 引用 |
| ---- | ---- | ---- |
| [基準1] | `path/to/file:12` | `その行（±2 行）に実在する文字列` |
| [基準2] | `cmd:test` | `ログに実在する文字列` |

### 総合

- **総合スコア**: 0.00（既定は基準スコアの単純平均。重み付き平均が必要な場合は渡された集計方法を使う）
- **品質ゲート**: [draft / review / production]（合格ライン: 0.00）
- **判定**: 合格 / 不合格 / 判定不能

### 修正指示（不合格または判定不能の場合）

命令形で書く。「〜が悪い」ではなく「〜を〜に変更せよ」。対象ファイルと変更内容を特定する。判定不能のときは「欠けた成果物を見ろ」（どのファイル、どのコマンド）と書く。

1. [対象ファイル]: [具体的な変更内容]
2. [対象ファイル]: [具体的な変更内容]

### 根拠を引用できない箇所（あれば）

- [どの基準について、何が見られなかったか]
```

採点時の注意:

- 「全体として良いか？」でまとめない
- 「根拠」表は照合スクリプト（`scripts/check_evidence.py check`）が機械で読む。列は 基準 / 場所 / 引用 の順に固定する
  - 場所は `path:行`（リポジトリ相対）か `cmd:名前`（`commands/<名前>.log` の記録）
  - 引用は、その行の前後 2 行以内、またはそのログに実在する文字列をそのまま写す。要約しない
  - 引用に `|` を含むときは `\|` と書く
  - 1 つの基準に根拠が複数あれば行を分ける
- 採点対象は差分が持ち込んだ挙動に限る。変更前からある挙動と diff の外は減点しない。変更前は `git show <base>:<path>` で読める
- 判定不能は合格にできない。該当基準のスコアは低くする
- 任意の改善提案はスコアカードの合否判定とは分け、「任意提案」として末尾に短く列挙してよい
