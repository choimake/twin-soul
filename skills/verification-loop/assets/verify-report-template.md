# 実行検証報告

実行検証サブエージェントは次の骨格で、ラウンドディレクトリの `verify-report.md` に書く。会話への返答は完了の一行だけにする。コマンドはすべて `scripts/check_evidence.py run` 経由で実行し、`commands/` に記録を残す。

```md
## 実行検証報告

- **対象**: [ブランチまたは commit]
- **使い捨て worktree**: [パス]（終わったら削除した / 削除できなかった理由）

### コマンド

| 名前（cmd:） | コマンド | 終了コード | 要旨 |
| ------------ | -------- | ---------- | ---- |
| test | [コマンド] | 0 | [一行で] |

### テストの効き目の確認（コード変更のとき）

前の周の一覧を引き継いで確かめ直す。テストが守れていない分岐が見つかれば行を足す。

| 名前（cmd:） | 守る分岐 | 戻し方 | 足した周 | 結果 |
| ------------ | -------- | ------ | -------- | ---- |
| red-1 | [テストが守る分岐] | [どの行をどう戻すか] | 1 | 落ちた / 落ちなかった |

### 動作確認（あれば）

| 手順 | 期待する観測 | 実際の観測 | 名前（cmd:） |
| ---- | ------------ | ---------- | ------------ |
| [手順] | [期待] | [実際] | smoke |

### 見つけた壊れ

- [何が、どの入力で、どう壊れたか。`cmd:名前` を添える。なければ「なし」]
```

注意:

- 実装は直さない。見つけた壊れは報告に書くだけにする
- 効き目の確認のコマンドは `red-` で始まる名前で記録する。照合スクリプトは `red-` の記録だけ「終了コード 0 以外」を期待どおりとして扱い、0 なら NG（落ちなかった）にする
- 確認が終わったら、戻した実装を元に戻す。使い捨て worktree はラウンドディレクトリの外に作る
- 戻しても出力が変わらない戻し方は、テスト不足ではない可能性がある。「落ちなかった」と書き、戻す前と戻した後の出力を並べて添える
