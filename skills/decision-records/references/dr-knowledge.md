# DR 判断知識

この資料は `decision-records` skill の判断知識をまとめたものである。`SKILL.md` は使い方に留め、新規作成や更新方針の詳細判断はこの資料とテンプレートを起点にする。

テンプレート:

- [../assets/dr-template.md](../assets/dr-template.md)

## DR の役割

Decision Record は、現在守るルールの要約ではなく、判断理由とその時点の背景を残す履歴である。

- 今どうしているかだけでなく、なぜそうしたかを残す
- 現行ルールが変わっても、過去の判断理由はその時点の文脈として保持する
- 現在の運用ルールや手順書そのものは README や `rules/`、`specs/` に寄せる

## 呼び出し側が渡せる入力

呼び出し側は、必要に応じて次を渡せる。

- 対象ディレクトリや対象 DR の `@path`
- `add` / `update` のような作業モード
- `review` / `draft` / `write-file` のような出力モード
- 既存 DR を探すための論点やキーワード

未指定なら、この skill が会話から妥当な既定値を判断する。必要最低限の確認だけを追加する。

出力モードの既定値:

- 方針だけ聞かれている場合は `review`
- 下書き、たたき台、テンプレートに沿った本文を求められた場合は `draft`
- 保存先が明示され、ファイル作成を依頼された場合だけ `write-file`
- 更新方針と本文の両方を求められている場合は `draft`

## 対象と探索の絞り方

1. ユーザーが `@path` で対象 DR や DR 保管ディレクトリ配下のドキュメントを指定したら、その対象を中心に扱う。
2. `add` / `update` が明示されていれば、それを優先する。未指定なら依頼内容から推定する。
3. `review` / `draft` / `write-file` が明示されていれば、それを優先する。未指定なら依頼内容から推定する。
4. 対象 DR や論点が曖昧なら、どの判断やテーマを扱うのか確認する。
5. 対象が曖昧な間は、確認質問だけを返し、具体的な更新案や本文修正には入らない。
6. 対象が決まったら、その論点に関係する既存 DR だけを確認すると明示する。
7. DR 保管ディレクトリの全件読了を前提にしない。まずは論点、ファイル名、キーワード、`ステータス` で関連 DR を絞る。
8. スコープ拡張が必要な場合は、まず現スコープで足りない理由と、追加で読みたいファイルを説明する。

## 更新判断

直接更新してよいのは、意味が変わらない軽微修正に限る。

- 誤字修正
- 表現調整
- リンク追加
- 補足追記

意味変更を含む更新では、既存 Accepted DR を直接最新化しない。

- 新しい DR を追加して supersede する
- 新しい DR に `Supersedes: <DR名>` を書く
- 古い DR に `Superseded by: <新DR名>` を追記する
- 関連 DR がある場合は `関連する DR` に記録する

## 新規追加の進め方

1. 新しい判断が必要な論点を一文で整理する。
2. 論点に関係する既存 DR を検索し、関係があるものだけ読む。
3. 関連 DR が見つからなければ、その旨と検索軸を示す。
4. 新規 DR が扱う範囲と、既存 DR と重ならない点を整理する。
5. `draft` または `write-file` なら、テンプレートをそのまま使って DR 本文を作る。

## 更新の進め方

1. 更新対象が軽微修正か意味変更かを先に判定する。
2. 軽微修正なら既存 DR を直接更新してよい。
3. 意味変更なら、新しい DR を追加して supersede する。
4. supersede する場合は、新しい DR に `Supersedes`、古い DR に `Superseded by` を書く。
5. ユーザーが既存 Accepted DR の上書きを希望しても、意味変更がある場合は直接更新を提案せず、supersede へ誘導する。
6. `draft` または `write-file` なら、テンプレートに沿って新しい DR の本文を作る。

## 出力モードごとの期待

### `review`

- 判断と進め方だけを返す
- DR 本文はまだ出さない

### `draft`

- まず短い説明で、対象範囲と判断を要約する
- 続けて `markdown` コードブロックで DR 本文全体を返す
- 本文にはテンプレートの章を省略しない

### `write-file`

- ユーザーが保存先の `@path` やファイルパスを明示したときだけ使う
- 実ファイルを書いた後に、作成先と判断内容を短く報告する
- 保存先が明示されていない場合は `write-file` に入らず、`draft` にフォールバックする

## 応答時の明示事項

対象が未指定のとき:

- まず対象 DR や論点を確認する短い質問だけを返す
- 対象が決まったら、関連 DR だけを確認して進めると添える
- DR 保管ディレクトリ全体を見に行く前提の説明や、具体的な修正案は出さない

新規追加の依頼では、返答の冒頭に次の文を入れる。

> `decisions/` の全件読了はせず、論点に関係する既存 DR だけを確認する。関連 DR があれば `関連する DR` に記録する。

意味変更を含む Accepted DR の更新では、`draft` のコードブロックより前に次を地の文で明示する。

- 意味変更を含むため、既存 Accepted DR を直接最新化しない
- 新しい DR を追加して supersede する
- 新しい DR に `Supersedes`、古い DR に `Superseded by` を書く
- 直接更新は意味が変わらない軽微修正だけに限る
