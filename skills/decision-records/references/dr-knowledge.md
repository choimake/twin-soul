# DR 判断知識

## DR の役割

Decision Record は、現在守るルールの要約ではなく、判断理由とその時点の背景を残す履歴である。

- 今どうしているかだけでなく、なぜそうしたかを残す
- 現行ルールが変わっても、過去の判断理由はその時点の文脈として保持する
- 現在の運用ルールや手順書そのものは README や `rules/`、`specs/` に寄せる

## 決定と値を分ける

値を DR に書くかは、値の種類ではなく、その値が意思決定に効いているかで決める。見分けるには、「その値を変える PR が来たとき、DR を読み直して議論し直す必要があるか」を問う。

- 意思決定に効いている値は書く。理由を一文で書けることが多い（例: server を常に 1 台動かす。0 台にすると待っている処理が時刻どおりに動かないため）
- 意思決定に効いていない値は外す。値は IaC・コード・設定に置き、その値にした理由は PR に書く。必要なら「値は実装を正とする」と書く
- 依頼に値が含まれていても、そのまま書き写さず、一つずつ意思決定に効いているかを見る
- 外した値だけを変えるときは、DR を足さず、既存 DR も直さない

## 出力モードの既定値

- 方針だけ聞かれている場合は `review`
- 下書き、たたき台、テンプレートに沿った本文を求められた場合は `draft`
- 保存先が明示され、ファイル作成を依頼された場合だけ `write-file`
- 更新方針と本文の両方を求められている場合は `draft`

## 更新判断

直接更新してよいのは、意味が変わらない軽微修正に限る。

- 誤字修正
- 表現調整
- リンク追加
- 補足追記

意味変更を含む更新では、既存 Accepted DR を直接最新化しない。新しい DR を追加し、変える範囲で次のどちらかにする。

判断全体を変える場合は supersede する。

- 新しい DR に置き換え元（例: `Supersedes: <DR名>`）を書く。表記は保管先の既存 DR に合わせる
- 古い DR に置き換え先（例: `Superseded by: <新DR名>`）を追記し、ステータスを Superseded にする

判断の一部だけを変え、残りは有効なままの場合は一部変更にする。

- 新しい DR の `関連する DR` に一部変更する DR（例: `一部変更する DR: <DR名>（変えた部分）`）を書く
- 古い DR のステータスは変えず、一部変更の行（例: `一部変更: <新DR名>（変えた部分、日付）`）を追記する
- 新しい DR の `判断` に、古い DR のうち変えない部分を書く
- 表記は保管先の既存 DR に合わせる

一部変更を足す前に、古い DR に付いている一部変更の行を数える。今回の分を合わせて `判断` の項目の大半が上書きされるなら、一部変更を重ねない。今の決定をまとめた DR を書き、古い DR と、それを一部変更した DR をまとめて supersede する。一部変更が重なると、今の決定を知るのに何本も読み合わせる必要があるため。

関連 DR がある場合は `関連する DR` に記録する。

## 提案中の DR

Proposed の DR は、まだ判断の履歴になっていないので、レビューを受けて直接書き換えてよい。

- 内容を変えても、ステータスは採否が決まるまで Proposed のままにする
- 採用が決まったら Accepted、提案ごと退けたら Rejected にする
- 内容に合わせてタイトルやファイル名を変えてよい。変える前に、その DR を参照している箇所を探す

## 採用しなかった判断

検討したうえで採用しなかった案も、同じ議論を繰り返さないために DR として残してよい。

- ステータスは Rejected にする。表記は保管先の既存 DR に合わせる
- `判断` に採用しなかった理由を書く
- `検討した選択肢` に、比べた案（今のまま続ける案を含む）を書く

## 新規追加の進め方

1. 関連 DR が見つからなければ、その旨と検索軸を示す。
2. ステータスの表記は保管先の既存 DR に合わせる。既存 DR が無ければテンプレートの表記を使う。

## 更新の進め方

- ユーザーが既存 Accepted DR の上書きを希望しても、意味変更がある場合は直接更新を提案せず、supersede か一部変更へ誘導する。

## 出力モードごとの期待

### `draft`

- `markdown` コードブロックで DR 本文全体を返す
- 古い DR に追記する行があれば、本文とは別に示す

### `write-file`

- 保存先が明示されていない場合は `write-file` に入らず、`draft` にフォールバックする

## 応答時の明示事項

対象が未指定のとき:

- まず対象 DR や論点を確認する短い質問だけを返す
- DR 保管ディレクトリ全体を見に行く前提の説明や、具体的な修正案は出さない

意味変更を含む Accepted DR の更新では、`draft` のコードブロックより前に次を地の文で明示する。

- 意味変更を含むため、既存 Accepted DR を直接最新化しない
- 新しい DR を追加して、supersede か一部変更にする。どちらにしたかと理由
- 古い DR と新しい DR の双方に書くリンク（表記は保管先の既存 DR に合わせる）
- 直接更新は意味が変わらない軽微修正だけに限る
