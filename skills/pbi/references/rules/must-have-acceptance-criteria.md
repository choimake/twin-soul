# 受入基準が明確に定義されているか（PBI）

## ねらい

受入基準が無いと「何ができたら完了か」が曖昧になり、スプリント後の認識齟齬や手戻りが起きる。検証可能な条件を明示し、PdM・開発・ステークホルダの合意点にする。

## チェック観点

- 「受入基準」またはそれに相当する見出し（例: `## 受入基準`, `## 受け入れ条件`）が存在するか
- 各項目が **検証可能** か（曖昧な形容詞だけで終わっていないか）
- チェックボックス形式（`- [ ]`）が使われているか（推奨）

## 指摘する基準

- 受入基準に相当するセクションが無い、または空の場合は **重大**
- 項目が曖昧すぎる（例: 「うまくいく」「問題ない」）場合は **重大**
- チェックボックス形式ではない場合は **提案**

## 例

### 悪い例

```markdown
## 受入基準

- 検証が完了している
- 関係者が納得している
```

### 良い例

```markdown
## 受入基準

- [ ] Fivetran 管理画面から Git 上の dbt プロジェクトと連携し、BigQuery で変換が実行できる
- [ ] 指定パッケージをインストールし、`dbt run` 後にスター型のマートが BigQuery に生成される
```

## 補足

- 技術検証 PBI では「ドキュメントに何が書かれていれば合意形成完了か」まで落とすとレビューしやすい
