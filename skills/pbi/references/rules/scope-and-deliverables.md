# スコープと成果物が文章上特定できるか（PBI）

## ねらい

コード変更のパス列挙に頼らず、PBI では **何を達成するか・何を作らないか・何に依存するか** を文章で特定できるようにする。コードパスが無い題材でもスコープが曖昧だと優先度判断ができない。

## チェック観点

- 「背景・目的」または「ゴール」に相当する記述があり、この PBI で達成したいことが読み取れるか
- 前提・依存（先行 PBI、外部システム、データの前提）が書かれているか
- 成果物のイメージ（ドキュメント、プロトタイプ、レポート等）が示されているか（該当する場合）

## 指摘する基準

- 背景・目的が無い、または「なんとなく改善」のように **何の PBI か判別できない** 場合は **重大**
- 前提・制約が空で、依存関係が読み取れない場合は **提案**
- スコープ外が明示されていないこと自体は必須としない（あると 任意）

## 例

### 悪い例

```markdown
## 背景・目的

データ連携をよくする
```

### 良い例

```markdown
## 背景・目的

先行 PBI で BigQuery に Raw が載っている前提で、Fivetran 経由の dbt 変換の実現可能性を検証する。本 PBI では本番 SLA や料金最適化は扱わない。
```

## 補足

- タスクブレイクダウンは標準セクションにしない。必要な短い作業メモは「メモ・論点」に含め、無くてもスコープが本文で読み取れればよい
