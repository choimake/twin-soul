# 参照・ベストプラクティスがあるか（PBI）

## ねらい

外部仕様・社内規約・ユーザーストーリー／受入基準の書き方など、参照があるとレビューと追跡がしやすい。PBI の参照セクションは必須を緩め、不足時は Web 検索またはユーザー追記を促す。

## チェック観点

- 「参考リンク」「参照」に相当するセクションがあるか
- 仕様 URL、社内 Doc、または関連 PBI へのリンクが 1 件以上あるか
- `draft` / `write-file` で Web 検索結果を参照に統合したか（可能な場合）

## 指摘する基準

- 参照セクションが完全に無い場合は **提案**
- 技術検証 PBI で公式ドキュメントへのリンクが無く、検証の根拠が曖昧な場合は **提案**（機密で外部 URL が無い場合は例外として説明があればよい）
- 参照が充実している場合は **任意** の指摘は出さない

## 例

### 悪い例

```markdown
## 参考リンク・仕様ドキュメント

（空）
```

### 良い例

```markdown
## 参考リンク・仕様ドキュメント

- [Fivetran Transformations](https://fivetran.com/docs/transformations): 実行・スケジュールの前提確認
- [INVEST - User Stories](https://www.agilealliance.org/glossary/invest/): ストーリー粒度の目安
```

## 補足

- 本ルール単独では **重大** にしない（他ルールと組み合わせて総合判断）
