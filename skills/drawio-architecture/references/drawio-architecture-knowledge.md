# draw.io 構成図 判断知識

この資料は `drawio-architecture` skill のデザインシステムと判断ルールである。`SKILL.md` は使い方に留め、余白・色・カード・線・分割の詳細はこの資料を起点にする。

視覚確認の合格条件と未完成条件は [visual-qa-checklist.md](visual-qa-checklist.md) を見る。

## 読み方

- 新規描画では「正本と成果物」「キャンバス」「色」「Card」「Edge」「Data plane と control plane」を先に読む
- 視覚修正では [visual-qa-checklist.md](visual-qa-checklist.md) を先に読み、この資料は寸法・色・線の定数確認に使う
- 公式 stencil を足すとき、または MCP が無いときは [mcp.md](mcp.md) を読む

## 正本と成果物

1. 事実の正本は、利用先リポジトリの yaml または同等の一覧である。そこに無い実リソースは足さない。
2. 見た目の正本はこの資料である。
3. 成果物は非圧縮の native draw.io（`mxfile` + `mxGraphModel`）である。
4. コードや正本から確認できないインフラは、事実ノードにしない。注釈にする。

## キャンバス

1. グリッドは 10 とする。
2. キャンバス外周の余白は 32 とする。
3. グループとグループの間隔は 32 とする。
4. ノードとノードの間隔は 24 とする。
5. データ面（リクエストと読み書き）は左から右とする。下向き本流は使わない。本流が縦になると、ホップの順が読みにくくなる。
6. 図は一つでなくてよい。データ面の概観に制御線（Management の紫破線）は置かない。制御線は別図とする。1 枚に同居させると回廊が埋まり、左から右の本流が読めなくなる。
7. 管理面だけの図では、ホップの始点を終点より左に置く。下向き本流は使わない。
8. 線は直交（orthogonal）または肘（elbow）とする。交差を避ける。
9. 手置きレイアウトを崩す一括再配置（ELK）は使わない。理由は [手置きと一括再配置](#手置きと一括再配置) である。

## 色

背景は非常に薄くする。カード本体は白とする。枠線に意味色を置く。

| 役割 | 用途 | 枠線 | ごく薄い背景 |
| --- | --- | --- | --- |
| Edge | エッジと設定の境界 | `#F6821F` | `#FFF8F3` |
| Cloud | クラウド実リソースの境界 | `#4285F4` | `#F3F8FE` |
| Data | 永続化とオブジェクト保管 | `#188038` | `#F1F8F3` |
| Management | 管理面の境界と制御線 | `#7B61C4` | `#F7F3FB` |
| Warning | 方針・注意・推測 | `#F9A825` | `#FFF8E1` |
| Neutral | 既定の線と本文 | `#5F6368` | `#F8F9FA` |

本文色は `#202124` とする。カード塗りは `#FFFFFF` とする。

箱のラベルは利用先の境界名に合わせてよい。意味色の役割は変えない。

## タイポ

1. フォントは Helvetica とする。
2. グループ見出しは 14px・太字とする。
3. カードのサービス名は 12px・太字とする。
4. 論理名と短い説明は 11px・通常とする。
5. エッジラベルは 11px とする。語数は 1〜3 語とする。
6. 注釈は 11px とする。一文にする。

## Container

プロバイダ境界や管理面は、見出し付きの container（swimlane）にする。

1. 見出し高さは 32 とする。
2. 内側余白は 24 とする。
3. 塗りは上表のごく薄い背景とする。
4. 枠線は対応する意味色とする。太さは 2 とする。
5. 子要素の座標は親からの相対とする。重ならないように置く。

## Card

サービスや設定はカードにする。詰め込みすぎない。

1. 最小サイズは幅 200・高さ 104 とする。標準も同じとする。3 行の日本語が枠で切れない高さを確保する。
2. 説明が長いときは幅を 10 の倍数で広げる。高さを下げて詰めない。
3. 角丸とする。白背景とする。枠線は 1 とする。
4. 1 行目はサービス名とする。
5. 2 行目は論理名とする。
6. 3 行目は短い説明とする。詳細は事実の正本か注釈へ移す。
7. 実リソースのカードは実線とする。
8. 設定だけのカードは破線とする。塗りは所属グループのごく薄い背景でも構わない。
9. データ系カードは Data の枠線色を使う。
10. 公式 stencil を足すときは、先にこの最小高さ 200×104 を満たしてからアイコンを置く。狭いカードへアイコンを足して文字を潰さない。

同じ並びで「製品上の設定」と「クラウド実リソース」を、同じ種類の実線カードとして置かない。設定は破線カードにする。

## Edge

1. データ面の線は Neutral・太さ 2・実線とする。
2. 管理面の線は Management・太さ 1・破線とする。
3. 矢印は終端だけとする。
4. ラベルは 1〜3 語とする。例は `HTTPS` / `write` / `read` / 経路名である。
5. データ面のホップは、始点を終点より左に置く。`source.x + width <= target.x` を目指す。
6. データ面の矢印は右辺から出て左辺に入る（`exitX=1` / `entryX=0`）。
7. 途中の直交ジョグ（短い上下）は、箱を避けるためだけに許す。ネットの進行方向は右とする。
8. 同じプロバイダ箱の中でも、本流を上から下に積んで下向き矢印にしない。幅が足りないときはキャンバスを広げるか、図を分割する。「箱に収めるため」は下向き本流の理由にならない。
9. 分岐は、どちらも分岐元の右に置く。一方を下に置いて下向き矢印にしない。
10. 線が箱を横切るときは、手置きを保ったまま経路だけを整理する。
11. ウェイポイントは 10 の倍数に載せる。
12. 同じ plane の線は、長さのある線分を共有しない。平行線は 10px 以上ずらす。ラベルが隣の線に乗るなら、さらにずらすか図を分ける。
13. 同じカードの同じ辺に、複数エッジを同じ点へ付けない。
14. 線はカード本文を貫通しない。回すか、図を分ける。
15. 層をまたぐ直交交差だけ `jumpStyle` で許す。同じ plane 同士の交差は、回すか図を分ける。
16. エッジラベルは最長の直線セグメントの中央に置く。線・箱・他ラベルから 6px 以上離す。
17. `labelBackgroundColor=#FFFFFF` だけでは足りない。白い箱が線の上に乗ったままだと読みにくい。
18. 1 枚の回廊に管理水平線が 2 本を超えるなら、増やす前に図を分割する。注釈へ落としてもよい。
19. 観測（ログ / トレース）は線にしない。注釈とする。

## Data plane と control plane

データ面と制御面を分けるのは、1 枚に混合すると回廊が埋まり、左から右の本流が読めなくなるためである。足りないから 1 枚に線を足すより、図を分ける。

1. 上段はリクエスト経路（data plane）とする。進行方向は左から右とする。
2. 概観に制御線（Management の紫破線）は置かない。管理カードを置いてよい。制御線は別図とする。
3. 制御面だけの図では、管理線（破線・紫）を左から右へ引く。下向き本流は使わない。
4. データ面と制御面を 1 枚に同居させて回廊を埋めない。

## Annotation

1. 注釈は Warning の枠とごく薄い背景とする。
2. コードから確認できないことは、事実カードにせず注釈にする。
3. 方針（望ましい設定や未観測の到達）は注釈とする。実機未観測の到達を断定しない。
4. 注釈はリクエスト本流の左下に 3 枚以上積まない。余白を圧迫するときは右端か管理面の空きへ移す。

## 公式 stencil

1. 公式 stencil は MCP の `search_shapes` が返した style だけ使う。ライブラリの shape 名を推測して書くと、公式と一致しない style になる。導入とツールの使い分けは [mcp.md](mcp.md) である。
2. `search_shapes` のタイトルが、カードの製品名と一致したときだけアイコンを足す。一致しない結果は捨てる。
3. 検索できないとき、または失敗したときは、同じクエリを連打しない。同じ失敗が続くだけなので、アイコンなしで進める。
4. アイコンはカードを 200×104 のまま、左に約 32px の子 shape として置く。カード自体をアイコンに置き換えない。
5. 視覚確認の周回には stencil 作業を混ぜない。狭いカードへアイコンを足すと文字がさらに潰れる。

## 手置きと一括再配置

1. 手置きした図に ELK の一括再配置（例: `postLayout: "elk"`）をかけない。ELK はノード位置を作り直すため、余白・カード間隔・左から右の流れが壊れる。
2. 交差整理だけが必要なときは libavoid（例: `routing: "libavoid"`）を使う。経路だけ直し、箱の位置は保つ。
3. 交差を消すためにカードの意味や事実の正本を変えない。見た目の問題は座標と経路で解く。
