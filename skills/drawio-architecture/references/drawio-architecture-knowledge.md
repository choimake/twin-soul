# draw.io 構成図 判断知識

この資料は `drawio-architecture` skill のデザインシステムと判断ルールです。`SKILL.md` は使い方に留め、余白・色・カード・線・分割の詳細はこの資料を起点にします。

視覚確認の合格条件と未完成条件は [visual-qa-checklist.md](visual-qa-checklist.md) を見てください。

## 読み方

- 新規描画では「正本と成果物」「キャンバス」「色」「Card」「Edge」「Data plane と control plane」を先に読みます
- 視覚修正では [visual-qa-checklist.md](visual-qa-checklist.md) を先に読み、この資料は寸法・色・線の定数確認に使います
- 公式 stencil を足すとき、または MCP が無いときは [mcp.md](mcp.md) を読みます

## 正本と成果物

1. 事実の正本は、利用先リポジトリの yaml または同等の一覧です。そこに無い実リソースを足しません。
2. 見た目の正本はこの資料です。
3. 成果物は非圧縮の native draw.io（`mxfile` + `mxGraphModel`）です。
4. コードや正本から確認できないインフラは、事実ノードにしません。注釈にします。

## キャンバス

1. グリッドは 10 です。
2. キャンバス外周の余白は 32 です。
3. グループとグループの間隔は 32 です。
4. ノードとノードの間隔は 24 です。
5. データ面（リクエストと読み書き）は左から右です。下向き本流は使いません。本流が縦になると、ホップの順が読みにくくなります。
6. 図は一つでなくてよいです。データ面の概観に制御線（Management の紫破線）を置かないでください。制御線は別図です。1 枚に同居させると回廊が埋まり、左から右の本流が読めなくなります。
7. 管理面だけの図では、ホップの始点を終点より左に置きます。下向き本流は使いません。
8. 線は直交（orthogonal）または肘（elbow）です。交差を避けます。
9. 手置きレイアウトを崩す一括再配置（ELK）は使いません。理由は [手置きと一括再配置](#手置きと一括再配置) です。

## 色

背景は非常に薄くします。カード本体は白です。枠線に意味色を置きます。

| 役割 | 用途 | 枠線 | ごく薄い背景 |
| --- | --- | --- | --- |
| Edge | エッジと設定の境界 | `#F6821F` | `#FFF8F3` |
| Cloud | クラウド実リソースの境界 | `#4285F4` | `#F3F8FE` |
| Data | 永続化とオブジェクト保管 | `#188038` | `#F1F8F3` |
| Management | 管理面の境界と制御線 | `#7B61C4` | `#F7F3FB` |
| Warning | 方針・注意・推測 | `#F9A825` | `#FFF8E1` |
| Neutral | 既定の線と本文 | `#5F6368` | `#F8F9FA` |

本文色は `#202124` です。カード塗りは `#FFFFFF` です。

箱のラベルは利用先の境界名に合わせてよいです。意味色の役割は変えません。

## タイポ

1. フォントは Helvetica です。
2. グループ見出しは 14px・太字です。
3. カードのサービス名は 12px・太字です。
4. 論理名と短い説明は 11px・通常です。
5. エッジラベルは 11px です。語数は 1〜3 語です。
6. 注釈は 11px です。一文にします。

## Container

プロバイダ境界や管理面は、見出し付きの container（swimlane）にします。

1. 見出し高さは 32 です。
2. 内側余白は 24 です。
3. 塗りは上表のごく薄い背景です。
4. 枠線は対応する意味色です。太さは 2 です。
5. 子要素の座標は親からの相対です。重ならないように置きます。

## Card

サービスや設定はカードにします。詰め込みすぎないでください。

1. 最小サイズは幅 200・高さ 104 です。標準も同じです。3 行の日本語が枠で切れない高さを確保します。
2. 説明が長いときは幅を 10 の倍数で広げます。高さを下げて詰めません。
3. 角丸です。白背景です。枠線は 1 です。
4. 1 行目はサービス名です。
5. 2 行目は論理名です。
6. 3 行目は短い説明です。詳細は事実の正本か注釈へ移します。
7. 実リソースのカードは実線です。
8. 設定だけのカードは破線です。塗りは所属グループのごく薄い背景でも構いません。
9. データ系カードは Data の枠線色を使います。
10. 公式 stencil を足すときは、先にこの最小高さ 200×104 を満たしてからアイコンを置きます。狭いカードへアイコンを足して文字を潰しません。

同じ並びで「製品上の設定」と「クラウド実リソース」を、同じ種類の実線カードとして置かないでください。設定は破線カードにします。

## Edge

1. データ面の線は Neutral・太さ 2・実線です。
2. 管理面の線は Management・太さ 1・破線です。
3. 矢印は終端だけです。
4. ラベルは 1〜3 語です。例は `HTTPS` / `write` / `read` / 経路名です。
5. データ面のホップは、始点を終点より左に置きます。`source.x + width <= target.x` を目指します。
6. データ面の矢印は右辺から出て左辺に入ります（`exitX=1` / `entryX=0`）。
7. 途中の直交ジョグ（短い上下）は、箱を避けるためだけに許します。ネットの進行方向は右です。
8. 同じプロバイダ箱の中でも、本流を上から下に積んで下向き矢印にしません。幅が足りないときはキャンバスを広げるか、図を分割します。「箱に収めるため」は下向き本流の理由になりません。
9. 分岐は、どちらも分岐元の右に置きます。一方を下に置いて下向き矢印にしません。
10. 線が箱を横切るときは、手置きを保ったまま経路だけを整理します。
11. ウェイポイントは 10 の倍数に載せます。
12. 同じ plane の線は、長さのある線分を共有しません。平行線は 10px 以上ずらします。ラベルが隣の線に乗るなら、さらにずらすか図を分けます。
13. 同じカードの同じ辺に、複数エッジを同じ点へ付けません。
14. 線はカード本文を貫通しません。回すか、図を分けます。
15. 層をまたぐ直交交差だけ `jumpStyle` で許します。同じ plane 同士の交差は、回すか図を分けます。
16. エッジラベルは最長の直線セグメントの中央に置きます。線・箱・他ラベルから 6px 以上離します。
17. `labelBackgroundColor=#FFFFFF` だけでは足りません。白い箱が線の上に乗ったままだと読みにくいです。
18. 1 枚の回廊に管理水平線が 2 本を超えるなら、増やす前に図を分割します。注釈へ落としてもよいです。
19. 観測（ログ / トレース）は線にしません。注釈です。

## Data plane と control plane

データ面と制御面を分けるのは、1 枚に混合すると回廊が埋まり、左から右の本流が読めなくなるためです。足りないから 1 枚に線を足すより、図を分けます。

1. 上段はリクエスト経路（data plane）です。進行方向は左から右です。
2. 概観に制御線（Management の紫破線）を置きません。管理カードを置いてよいです。制御線は別図です。
3. 制御面だけの図では、管理線（破線・紫）を左から右へ引きます。下向き本流は使いません。
4. データ面と制御面を 1 枚に同居させて回廊を埋めないでください。

## Annotation

1. 注釈は Warning の枠とごく薄い背景です。
2. コードから確認できないことは、事実カードにせず注釈にします。
3. 方針（望ましい設定や未観測の到達）は注釈です。実機未観測の到達を断定しないでください。
4. 注釈はリクエスト本流の左下に 3 枚以上積みません。余白を圧迫するときは右端か管理面の空きへ移します。

## 公式 stencil

1. 公式 stencil は MCP の `search_shapes` が返した style だけ使います。ライブラリの shape 名を推測して書くと、公式と一致しない style になります。導入とツールの使い分けは [mcp.md](mcp.md) です。
2. `search_shapes` のタイトルが、カードの製品名と一致したときだけアイコンを足します。一致しない結果は捨てます。
3. 検索できないとき、または失敗したときは、同じクエリを連打しません。同じ失敗が続くだけなので、アイコンなしで進めます。
4. アイコンはカードを 200×104 のまま、左に約 32px の子 shape として置きます。カード自体をアイコンに置き換えません。
5. 視覚確認の周回には stencil 作業を混ぜません。狭いカードへアイコンを足すと文字がさらに潰れます。

## 手置きと一括再配置

1. 手置きした図に ELK の一括再配置（例: `postLayout: "elk"`）をかけません。ELK はノード位置を作り直すため、余白・カード間隔・左から右の流れが壊れます。
2. 交差整理だけが必要なときは libavoid（例: `routing: "libavoid"`）を使います。経路だけ直し、箱の位置は保ちます。
3. 交差を消すためにカードの意味や事実の正本を変えません。見た目の問題は座標と経路で解きます。
