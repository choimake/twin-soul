# 構成図の視覚確認チェックリスト

この資料は `drawio-architecture` skill の完了判定である。描画ルールの定数は [drawio-architecture-knowledge.md](drawio-architecture-knowledge.md) を見る。

XML が valid でも、文字切れと線の重なりは分からない。MCP の `create_diagram` プレビューも縮小レンダリングで、同じ欠落がある。合格は人が draw.io で開いたスクショで判定する。

## いつ読むか

- 新規描画のあと、完了と言う前
- 視覚修正の依頼を受けたとき
- レビューで「見た目は十分か」を判定するとき

## 手順

1. draw.io（デスクトップまたは `app.diagrams.net`）で対象の `.drawio` を開く。
2. 全体のスクショを 1 枚撮る。
3. 潰れている箇所、線が字に被っている箇所の部分スクショを撮る。
4. チャットに貼る。エージェントは画像を見て、座標・ウェイポイント・カード寸法・ラベル位置だけ直す。
5. 事実の正本は触らない。公式 stencil は同じ周回に混ぜない。
6. 生成、スクショ、修正を 2 周から 3 周で止める。

スクショが無いときは、座標を推測で直さない。全体と潰れている部分の画像を求めてから直す。

自動スクリーンショット基盤（Desktop CLI やヘッドレス）は必須にしない。人手のスクショで足りる。

## 止めどき（すべて満たす）

次をすべて満たしたら止める。

1. カード内テキストが枠で切れていない。
2. エッジラベルが線・箱・他ラベルと重なっていない。
3. 同じ plane の線が同じ線分を共有していない。線がカード本文を貫通していない。
4. 概観に制御線（Management の紫破線）が無い。
5. 5 秒見て、意味色の役割（エッジ / クラウド / データ / 管理 / 注意 / 中立）と、その図で置いた境界の違いが分かる。
6. データ面の本流が左から右に読める。下向きのリクエスト矢印が無い。

## 完成にしないもの

次は完成条件にしない。

1. MCP の `create_diagram` だけで見たこと。プレビューは縮小画像で、重なりや文字切れは見えない。
2. XML の parse 成功だけ。構文が通っても重なりは分からない。
3. 公式 stencil の有無。アイコンが無くても、上の 6 条件を満たせば視覚確認は終わりである。

## 視覚修正で直してよいもの

- 座標
- ウェイポイント
- カード寸法
- ラベル位置

事実の正本、ノードの意味、エッジの有無は触らない。2 周から 3 周で止まり、まだ潰れている箇所があれば、残件として返す。
