# 技術の入門教材

## 目的

その技術を初めて扱うソフトウェアエンジニアに、少数の要点を持ち帰らせる。読み終えた人は、何であるか、どう動くか、代表的な構造とパラメータが動きのどこに効くかを、自分の言葉で言える。中心は動きである。網羅はしない。

## 使う場面

- 「この技術の勉強をしよう」「入門資料を作って」「何も知らないエンジニア向けに説明して」と言われたとき
- 公式ドキュメントがある題材を、一枚の HTML の入門にしたいとき

対象外である。

- 前提知識ゼロの一般向け説明（eli5）
- draw.io の構成図を描く作業（drawio-architecture）
- 環境構築や SDK 導入だけの手順書
- 失敗談を入口にするエッセイ
- 試験対策の枠、章末の演習、模擬問題、操作コマンドの章

## 手順

最初に [references/tech-intro-knowledge.md](references/tech-intro-knowledge.md) を読む。判断はすべてそちらにある。

1. 対象の使い方と版を決める。分からなければ着手前に1回だけ聞く。公式ドキュメントが無ければ未確認だけを返す
2. 書く前に、読み手、要点（3〜5個）、一例を決める（references の「読み手」「要点を絞る」）
3. 公式ドキュメントで事実を確かめる。使うのは要点に効く事実だけである。AI エージェント用の公式 skill の有無も確かめる（references の「調べ方」「公式 skill」）
4. 2部で書く。第1部「仕組み」は厚く、第2部「使い始めるとき」は短くする（references の「章立て」「章の中」「動き」「図」）
5. `python3 scripts/check-html.py <出力 HTML>` が終了コード 0 になるまで直す。そのあと references の「点検」を目で見る

1 から 5 は、1つのモデルで最後まで通せる。調査や執筆を別のモデルやサブエージェントに分けてもよいが、分けることを前提にしない。

## 期待する出力

- CSS と同梱した単一 HTML。script は確認クイズの採点だけ
- 冒頭に要点（`data-goals`、5個まで）がある。対象、版、確認日、扱わないものの注記は、出典と同じく閉じた `<details data-scope>` に入っている
- 第1部で、何であるか、なぜ要るか、登場人物、動き、構造とパラメータが分かる。主な動きは動く図で見せる
- 第2部は短い。選び方、担い手、比べる相手、本番、上限を表か図で済ませ、AI エージェント用の公式 skill の章（`data-agent-skills`）がある
- 見出しは25字までの短い主張で、章の結論は章の最初の1文にある
- 幅 375px でも横にスクロールしない。暗い配色でも読める
- 各章に出典がある。確かめられなかったことは末尾にまとまっている

## 検証

- `name` は親ディレクトリ名 `tech-intro` と一致している
- `description` は `>-` で 1024 文字以内。WHAT と WHEN、起動される依頼、対象外との境界が見える
- `SKILL.md` は手順に留まり、判断は `references/tech-intro-knowledge.md` にある
- `python3 scripts/check-html.py --self-test` が終了コード 0 である。出力 HTML も同じスクリプトで終了コード 0 である
